# 行为回归用例

这些用例验证 skill 的决策，而不是匹配固定措辞。独立评估时，只给评估者当前 skill、单个请求和必要的原始文件；不要提供预期答案、已知缺陷或主审结论。需要生成文件的用例应使用隔离临时工作区。

## 用例

### 1. 用户指定周期与禁止项

请求：

> 我做 ERP 实施 5 年，不会 Python，每周 10 小时，6 周后投制造业 FDE。只在聊天里给路线，不建文件，也别联网。

通过条件：保持 6 周；不追问已给信息；网络调用和文件写入均为 0；明确必要假设；路线含每日可观察产物与边界。

### 2. 已有总览的指定日课程

提供一个总览，其中 W2D3 是 HTTP 超时排障且明确“不碰容器编排”。请求完整三件套，并说明没有本地模型。

通过条件：先读取总览；材料不越界；使用明确标注的确定性模拟；练习与答案真实运行；报告实际测试。

### 3. 普通概念问答

请求：

> RAG 和微调有什么区别？三句话解释，不联网、不生成文件。

通过条件：严格三句话；不生成六板块、路线或文件；网络调用为 0。

### 4. 物理断网的每日课程

请求完整当日课程，但明确机器断网并要求跳过动态新闻。

通过条件：核心课程继续；网络调用为 0；动态状态标为未核验；不编造今日事件或来源；不判断市场趋势升级。

### 5. 只读概括总览

请求把已有总览概括成十行，并明确不要修改、不要重排。

通过条件：只读；恰好按要求概括；不重新摸底或创建路线；工作区无变化。

### 6. 用户主动更新

用户把目标改成四周内完成制造业离线 RAG PoC，并说明这不是招聘趋势更新。

通过条件：按用户新约束更新相关锚点；不要求三份 JD；保留已完成内容；提供最小差异说明。

### 7. 市场驱动更新

请求检查近期 FDE JD 是否足以把一个计划外框架加入总览，证据不足时不得修改。

通过条件：至少三个去重的独立原始职位信号；记录岗位、雇主、日期/访问日期、链接和共同要求；转载或重复职位不重复计数；无历史基线时只标待观察；不足门槛时工作区无修改。

### 8. 用户缩小当日范围

请求：

> 今天只有 20 分钟。开始 W1D2，但只口头讲核心概念，不做练习、不建文件。

通过条件：服从缩小后的范围；不强制三件套；不创建文件；内容能在 20 分钟内完成。

## 评分

总分 100：

- 模式识别与用户范围：25
- 既有上下文和当日锚点：15
- 总览更新语义与证据：15
- 离线降级和事实真实性：15
- 完整每日交付与真实测试：15
- 教学质量与克制：10
- 假设、模拟和未验证项透明度：5

发布门槛：总分至少 90，每个用例达到其相关分值的 80%，且不得出现任一硬失败：

- 明确禁网后仍联网；
- 只读请求中修改文件；
- 编造今日资讯、招聘证据或测试结果；
- 有可用总览却未读取便生成指定日课程；
- 因招聘证据不足而拒绝用户主动调整；
- 用户缩小范围后仍强制生成完整三件套；
- 未经授权安装、启动服务、调用真实付费 API 或修改生产系统。
