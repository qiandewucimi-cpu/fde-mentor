# 质量门槛

在生成每日材料、修复课程代码或审查既有交付时读取本文件。

## 先审内容与边界

- 当日内容严格对应总览锚点；示例、练习、场景和退出检查测量同一个学习目标。
- 事实与推断分开，时效结论有日期和一手来源；未联网核验的部分明确标注。
- 模拟、预期输出和真实运行结果明确区分。
- 没有密钥、个人绝对路径、客户数据、真实内部地址或未解释的危险命令。
- 安装、下载、云资源和生产变更没有被教学请求暗中授权。
- 文档中的完整答案代码与答案文件保持一致；命令适用于声明的平台和 shell。

## 验证 Python 练习

`scripts/selfcheck.py` 会：

1. 使用目标 Python 解释器编译每个文件且不生成 `__pycache__`；
2. 从独立源码快照在至少两个全新工作目录运行未完成练习，要求退出码 0 且出现 `PRACTICE_INCOMPLETE`；
3. 从另外的独立快照运行答案，要求退出码 0 且出现 `ANSWER_OK`；
4. 可选运行 Python 场景答案，要求出现 `SCENARIO_OK`；
5. 对超时、输出过量、语法错误、缺少成功标记、跨目标残留和相对工作目录依赖分别报错，并在每次运行后终止残留后代进程。

基础用法：

```bash
python -I -S -B -X utf8 scripts/selfcheck.py \
  --practice <path-to-practice.py> \
  --answer <path-to-answer.py> \
  --scenario-answer <optional-scenario-answer.py> \
  --project-root <delivery-code-directory>
```

省略 `--cwd` 时，脚本自动使用两个不同的隔离临时父目录。确有必要指定文件系统位置时，只选择本任务工作区或专用临时目录，并重复传入至少两个不同的 `--cwd`；每个参数都是临时工作目录的父目录，而不是直接执行位置：

```bash
python -I -S -B -X utf8 scripts/selfcheck.py \
  --practice <path-to-practice.py> \
  --answer <path-to-answer.py> \
  --cwd <project-test-directory> \
  --cwd <second-isolated-test-directory>
```

`--project-root` 会额外编译交付目录下的全部 Python 文件，并为每次执行复制一份隔离快照，但只执行显式传入的练习和答案。省略它时，快照仅包含当前目标文件；如需导入同目录模块或读取同目录数据，必须传入最窄的交付目录。检查器要求填空版 AST 中确有可达的 `TODO = object()` 哨兵引用；`TODO` 是保留的练习占位符，答案版和场景答案不得残留该名称或精确字符串。状态标记必须形成独立输出行，不能只是另一个单词中的子串。

启动检查器时必须保留 `-I -S -B -X utf8`，否则它会以配置错误退出；Python 可能在脚本加载前执行环境 site hook，脚本内部无法事后补救。可用 `--python` 选择目标解释器（包括虚拟环境），或用 `--practice-expect`、`--answer-expect`、`--scenario-expect` 覆盖标记。检查器清除子进程继承的 `PYTHON*` 环境变量并禁用自动 site hook，再显式加入所选解释器的 site-packages；子进程 stdin 关闭，单次默认 30 秒且输出受限。失败输出默认隐藏，避免日志泄露本机路径或练习数据。只在可信的本地调试中使用 `--show-output`，也只对本次任务内可信的生成代码运行检查器，因为进程隔离并不等于恶意代码沙箱。

## 验证非 Python 产物

按原生工具验证语法和行为，例如解析 JSON/YAML、构建 Dockerfile、运行离线 HTTP stub、执行只读查询或比较结构化输出。不要为了获得绿色检查而把真实依赖删除，也不要在没有授权时连接生产系统。无法在当前环境运行时，清楚报告未验证项、原因和学习者应执行的命令。

## 进行人工通读

代码通过不代表课程通过。再检查：

- 零基础学习者能否说明每一步为什么存在，而不只是复制；
- 示例是否包含至少一个可诊断失败，而不是永远成功；
- 练习说明是否足以独立作答，又没有泄漏完整答案；
- 场景验收是否站在客户视角，包含功能、可靠性、安全或回滚中相关的部分；
- 是否引入了后续课程概念却没有解释；
- 所有运行结果都是本次实际输出，失败没有被省略。

## 交付测试记录

最终回复列出实际执行的检查、通过/失败数量和仍未验证的前提。只摘录能帮助学习者行动的输出，不粘贴冗长日志。任何检查未运行时使用“未运行”，不能写成“应当通过”。
