# 每日课程交付

只在生成、重做或复习某一天的学习材料时读取本文件。

## 锁定当日范围

先读取总览中对应的每日锚点，提取当日目标、必须覆盖、明确边界、产物和退出检查。若找不到总览，不要编造此前进度：为本次课程声明一个临时单日锚点和必要假设；只有用户要求时才补建完整路线。

重做或复习时先判断失败发生在概念、语法、环境还是排障策略，再替换练习或讲法。不要原样重复已经无效的材料。

用户缩小指定日范围或给出时间盒时，只交付被请求的部分，并让内容能在该时间内完成。明确哪些默认内容被省略，不要强制生成练习、文件、动态框或完整三件套。

## 默认交付结构

完整三件套指“教学讲义 + 基础练习及答案 + 客户场景及参考答案”。用户请求完整课程且有可写工作区时使用下列结构；已有项目有清晰约定时服从项目约定：

```text
<week-or-module>/
|-- DayX_<topic>.md
`-- code/
    |-- practice/
    |   |-- wX_Y_practice.py
    |   `-- wX_Y_practice_answer.py
    `-- scenario/
        |-- wX_Y_scenario.md
        `-- wX_Y_scenario_answer.py   # 仅当 Python 是场景的自然解法
```

如果场景的自然产物是 Dockerfile、配置、SQL、Shell 或排障记录，就交付并验证该原生产物，不要为了符合目录示例伪造一个 Python 答案。

## 教学文档

文档应让以下六个学习视角清晰可辨；可以为阅读流畅而合并相邻小节，不要制造同义重复标题：

1. **一句话总结**：今天解决什么客户问题，完成标准是什么。
2. **核心要点**：先给生活化心智模型，再给术语和完整代码全景，随后解释关键函数、参数与数据流。
3. **岗位启发**：它在发现需求、集成、部署、排障或验收中的作用，以及面试如何验证真实理解。
4. **批判性思考**：何时不应使用、主要失败模式、成本和替代方案。
5. **拓展思考**：只指出与后续锚点有关的延伸，不提前教授越界内容。
6. **行动建议**：按顺序列出要读、要改、要运行和要自检的动作。

新概念先解释动机，再用一个具体例子说明定义。参数存在明显取舍时用小型对照表展示后果，不给脱离上下文的“万能默认值”。关键 API 至少说明：输入和输出、为何需要、关键参数为何这样选、失败时看到什么信号。

“今日岗位动向”和“今日 AI 动态”仅在已联网核验且与当日目标相关时提供，写明日期并附一手来源。若未核验，用一句状态说明代替内容，不用旧闻填框。

## 基础练习

练习验证当日目标，不考尚未教授的知识：

- 填空版必须保持语法有效。优先使用可识别的哨兵值，例如 `TODO = object()` 与 `value = TODO`，再用 `is TODO` 统计未完成项；不要靠全文字符串计数判断 TODO。将 `TODO` 保留给这一哨兵，完整答案和场景答案中不得再使用该名称或精确字符串。
- 未完成时打印 `PRACTICE_INCOMPLETE remaining=<n>` 并以退出码 0 结束，不进入真实逻辑。
- 填完后运行实际逻辑和断言，不能只打印预设答案。
- 答案版与文档中的完整代码全景保持一致，执行实际逻辑与断言，成功时打印 `ANSWER_OK`。
- 外部模型、云服务或客户 API 不是当日重点时使用确定性模拟；模拟要显式标注，注入可控的成功与失败结果。
- 文件访问基于脚本位置或显式参数，不能依赖启动时的工作目录。

练习应包含可观察的失败信息，让学习者能判断是占位未填、输入无效、依赖缺失还是程序逻辑错误。

## 客户场景题

场景应包含真实约束，例如离线环境、接口超时、配置漂移、容器网络、资源上限、验收口径或回滚要求。用四段式组织：

1. **速查卡**：当天已经学过的命令、信号和记忆钩子；
2. **师傅示范**：演示如何收集证据、提出假设、缩小范围和验证；
3. **决策表**：把观察到的信号映射到下一步检查，而不是直接映射到唯一答案；
4. **独立任务**：只给客户背景、限制、可用证据和验收标准，让学习者从零形成方案。

参考答案必须说明排障顺序、证据、取舍、客户沟通与回滚。能自动验证的产物加入断言或离线检查，Python 场景答案成功时打印 `SCENARIO_OK`。

## 自检题

用 5 道左右的高信号问题覆盖：技术动机、数据或控制流、参数取舍、失败诊断和客户验收。题量服务于当日目标；简单课程不为凑数重复提问。答案应可从讲义和实际运行结果中推导。
